### File Schema & Format
- **Format**: TSV (`\t` delimited), UTF-8 encoded, with header.
- **Columns**:
  1. `source1_entity_id` (VARCHAR): Canonical $S_1$ entity identifier (e.g., `S1-123456789`).
  2. `matched_entity_id` (VARCHAR): Canonical target entity identifier (e.g., `S2-987654321` or `S3-987654321`).
- **Ordering**: Deterministically sorted by `source1_entity_id ASC, matched_entity_id ASC`.

## 2. Retrieval Configuration Provenance
The production V3 candidate universe is generated by combining:
1. **Frozen V2 Baseline Rules** (Rules A through I: exact address, prefix4+house, token overlap, phone, tax/reg IDs).
2. **EXP-RET-01**: Soft Name Retrieval (Country + `core_name` len $\ge 5$, deterministic S1 fanout cap $\le 100$).
3. **EXP-RET-02**: Relaxed Name + House Retrieval (Country + `house_norm` + `name_prefix_2` + Jaro-Winkler $\ge 0.80$, deterministic S1 fanout cap $\le 50$).
4. **EXP-RET-03**: Indic / Transliteration-Aware Retrieval (Devanagari ISO 15919 transliteration + cross-script address block, deterministic S1 fanout cap $\le 50$).
5. **EXP-RET-04**: Locality + Name Retrieval (Country + address prefix 10 + name prefix 3 + Country + postal_code len $\ge 5$ + root_token len $\ge 4$).

### Exact Reproduction Command
```bash
python3 P1/scripts/retrieval/generate_v3_candidates.py --split all
```
